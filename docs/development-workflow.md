# Development Workflow for Agents

This repo is active multi-agent territory. Work narrowly, verify against the current tree, and do not touch files outside the requested scope.

## First-Read Order

1. `AGENTS.md` when present (local, not in git) for agent rules, build expectations, and references.
2. `AGENTS.local.md` when present for checkout-specific constraints.
3. `docs/codebase-map.md` for code boundaries and the current mental model.
4. `docs/product-and-scope.md` for product intent and long-lived constraints.
5. `STYLE.md` before any UI change.
6. `project.yml` before source-file, target, resource, or framework changes.
7. `README.md` for public setup and feature status.
8. Source layout with `find Ithaca/Sources -maxdepth 3 -type f | sort`.

Docs can lag source. Confirm current behavior in code before making specific claims.

## Source-of-Truth Files

- `project.yml`: Xcode targets, schemes, sources, resources, deployment targets, framework embedding, Swift settings.
- `Ithaca.xcodeproj`: generated by XcodeGen; keep it synced, do not hand-edit it.
- `STYLE.md`: visual tokens, materials, spacing, typography, and UI guardrails.
- `docs/codebase-map.md`: intended code boundaries and extension patterns.
- `docs/product-and-scope.md`: product requirements and non-goals; check
  `project.yml` for current platform details.
- `Frameworks/`: vendored VLCKit binaries and the locally built
  `IthacaDovi.xcframework` (all git-ignored). Refresh VLCKit only when explicitly asked.
- `Native/IthacaDovi/`: the Rust crate behind `IthacaDovi.xcframework` (Dolby Vision 7 → 8.1
  sample conversion over quietvoid's `dolby_vision`); its C header is the frozen ABI.

## Where New Files Go

- App entry, theme, and navigation shell code: `Ithaca/Sources/App/`.
- New Plex endpoints: the matching `PlexService+*.swift` concern file.
- Plex response and app-facing media types: `Ithaca/Sources/Models/`.
- Playback engine details: `Ithaca/Sources/Playback/`.
- Player UI, overlays, sheets, and coordinator behavior: `Features/Player/`.
- Detail screens and detail-only shared pieces: `Features/Detail/`.
- Broad reusable UI, formatting, and presentation helpers: `Shared/`.
- Offline download implementation: `Ithaca/Sources/Downloads/`.
- Download-facing screens: `Ithaca/Sources/Features/Downloads/`.
- Resources: `Ithaca/Resources/`; iOS support plist files: `Ithaca/Support/`.

Prefer existing files and same-type extension patterns for small additions. Add a file when the code is a distinct concept or an existing type is already split by concern.

## Architectural Guardrails

- Plex is the only backend. Do not add provider abstractions without a real second backend.
- Views do not call the network directly. SwiftUI views talk to `@Observable` view models; view models call `PlexService`.
- Use async/await. Avoid Combine except when wrapping callback APIs.
- Keep AVPlayer/VLCKit specifics in `Playback/` behind `PlaybackEngine`.
- Keep engine-agnostic player UI in `Features/Player/`.
- Use platform-specific shells for meaningful iOS/tvOS layout differences.
- Use `#if os(tvOS)` close to platform-specific behavior.
- Direct play is the startup baseline. Manual quality changes may request Plex
  transcoding, but stored preferences must not start video transcoding
  automatically.

## Style Guardrails

- Native vibes, not orange: system controls and Liquid Glass first, no colour tint on them.
- Use `Color.ithacaBackground`, `Color.ithacaSurface`, `Color.ithacaTextPrimary`, and `Color.ithacaTextSecondary`. `Color.ithacaAccent` is the brand accent only (logo/icon), never a UI tint.
- Do not introduce ad-hoc UI colors such as `.orange`, `.blue`, `.green`, or `.purple`.
- Use system materials where `STYLE.md` calls for glass overlays/navigation.
- Follow `STYLE.md` for radii, borders, typography, and tvOS focus treatment.

## XcodeGen and Project Maintenance

- Edit `project.yml` for project settings, targets, resources, frameworks, or deployment target changes.
- Run `xcodegen generate` after changing `project.yml`.
- Run `xcodegen generate` after adding, removing, or renaming files under `Ithaca/Sources`.
- Commit regenerated `Ithaca.xcodeproj` only when it changed because of your intentional project/source-file change.
- If `xcodegen` is unavailable, report the verification gap instead of hand-editing generated project files.

## VLCKit Bootstrap

- `ci_scripts/ci_post_clone.sh` (Xcode Cloud) calls `ci_scripts/install_vlckit.sh`
  to fetch both framework archives before any target builds. Run the installer
  once locally after cloning.
- The default install is VideoLAN's stock 3.7.3 (public CocoaPods archives,
  thinned to arm64, checksum-pinned). The app builds and runs with it; Playback
  Info's "VLCKit Build" row says "Stock VLCKit 3.x" and TrueHD goes through
  Plex. Network, TLS, and CDN transfer failures are retried, with partial
  downloads resumed; do not weaken the checksum.
- To use a local TrueHD-enabled build instead, run `ci_scripts/build_vlckit.sh`
  and install its output with
  `ITHACA_VLCKIT_CACHE_DIR=.build/vlckit/out ci_scripts/install_vlckit.sh`
  (see VLCKit Build). The installer verifies the archives against the
  `.sha256` files the build wrote next to them.
- "Already installed" is decided from each slice's `IthacaVLCKitBuild` stamp
  (local build) or the `vlckit-installed.txt` marker the installer writes into
  each xcframework (stock), never from the tracked `Frameworks/VLCKit-VERSION.txt`.

## VLCKit Build

- `ci_scripts/build_vlckit.sh [ios|tvos|all]` builds MobileVLCKit/TVVLCKit
  from source: VLCKit tag 3.7.4 (pinned commit, libvlc 3.0.24 at VLCKit's
  tested hash), arm64 device + arm64 simulator slices. Manual only; nothing
  in CI runs it. iOS and tvOS use separate trees under `.build/vlckit/`, so
  `build_vlckit.sh ios & build_vlckit.sh tvos` runs both in parallel. A cold
  build compiles VLC's own toolchain and every contrib; trees are reused, and
  `ITHACA_VLCKIT_CLEAN=1` starts over. Logs: `.build/vlckit/<platform>.log`.
- Patches: `ci_scripts/vlckit-patches/` apply to the VLCKit checkout (build
  script: arm64-only packaging, iOS/tvOS 15 minimum, current Xcode);
  `ci_scripts/vlc-patches/` (0100+) are appended to VLCKit's own libvlc
  series, which `buildMobileVLCKit.sh` git-am's onto vlc. 0100 re-enables
  TrueHD/MLP (read "Dolby TrueHD decoding" in `playback.md` for the licensing
  decision), 0101 fixes tvOS multichannel output, 0102 fetches the Apache
  build tools (Ant) from archive.apache.org, since downloads.apache.org drops
  old releases, 0103 builds VLC's own `zstd` tool without lzma/lz4 (an
  Intel Homebrew left in `/usr/local` otherwise breaks its arm64 link), and
  0104 keeps meson's ninja (Kitware's jobserver fork, from VLC's tools) out
  of make's jobserver, which the GNU make 3.81 macOS ships cannot share with
  it, 0105 builds librist with its bundled lz4 (it otherwise links an
  Intel Homebrew `liblz4` from `/usr/local`, and the framework link fails),
  0106 labels 5.1 side channels as surround in the CoreAudio output, and
  0107 keeps the tvOS route multichannel between titles (see the
  multichannel notes in `playback.md`).
- The App Store build ships this VLCKit, so the LGPL source offer is the public
  repo `inceptyon-labs/ithaca-vlckit` (`~/Development/ithaca-vlckit`), named in
  `ThirdPartyNotices.txt`. When a patch or `build_vlckit.sh` changes, copy
  `ci_scripts/build_vlckit.sh`, `vlc-patches/` and `vlckit-patches/` there, update
  its README's patch list and version, and push it before the next release.
- The script fails unless `libavcodec.a` defines `ff_truehd_decoder` and
  `ff_mlp_decoder`, stamps each framework's Info.plist (`IthacaVLCKitBuild`,
  `IthacaVLCKitTrueHD`, read by `VLCKitBuildInfo`), and writes
  `<Name>-<version>.tar.xz` + `.sha256` to `.build/vlckit/out/`.
- After changing the patches, bump `ITHACA_VLCKIT_BUILD` in `build_vlckit.sh`
  and `VLCKIT_VERSION` in `install_vlckit.sh` together, build both platforms,
  and install with
  `ITHACA_VLCKIT_CACHE_DIR=.build/vlckit/out ci_scripts/install_vlckit.sh`.
- The libvlc version string stays `3.0.x`; the stamp is what distinguishes
  Ithaca's build from VideoLAN's.

## IthacaDovi Bootstrap

- `Frameworks/IthacaDovi.xcframework` is a static library (iOS + tvOS, device + simulator,
  arm64 only) built from `Native/IthacaDovi` and linked into both apps, never embedded.
  It is git-ignored; after cloning run `./ci_scripts/install_ithaca_dovi.sh` once (needs
  [rustup](https://rustup.rs)). `ci_post_clone.sh` runs it too, installing rustup on CI
  from a pinned `rustup-init` (version and per-architecture SHA-256 in the script, picked
  with `uname -m`); bump all three together.
- The installer stamps a hash of the crate, `Cargo.lock`, the toolchain pin, the build
  script and the `project.yml` deployment targets into the xcframework, and is a no-op
  until one of them changes. `scripts/build_ithaca_dovi_xcframework.sh` forces a rebuild.
- Toolchain: pinned in `Native/IthacaDovi/rust-toolchain.toml`, installed with the four
  Apple targets on demand. Deployment targets are read from `project.yml`.
- Homebrew trap: `/opt/homebrew/bin/cargo` and `rustc` usually come first on PATH and
  have no iOS/tvOS standard library (`can't find crate for core`). Recent rustup no
  longer puts the toolchain first on PATH for `rustup run`, so even
  `rustup run 1.99.1 cargo build` reaches Homebrew's `rustc`. The build script pins
  `RUSTC` and cargo via `rustup which`; do the same for manual builds:
  `RUSTC="$(rustup which rustc --toolchain 1.99.1)" "$(rustup which cargo --toolchain 1.99.1)" test --manifest-path Native/IthacaDovi/Cargo.toml`.
- Changing `ithaca_dovi.h` means bumping `ITHACA_DOVI_ABI_VERSION` (and the check in
  `DoviBridgeTests`). New crates in `Cargo.lock` need an entry in
  `Ithaca/Resources/ThirdPartyNotices.txt` and `Native/IthacaDovi/THIRD_PARTY_LICENSES.md`.

## Verification Commands

After code changes, run compile-only verification. Do not run tests or launch the app/simulator unless asked.

```bash
xcodebuild -project Ithaca.xcodeproj -scheme Ithaca -configuration Debug -destination 'generic/platform=iOS Simulator' ARCHS=arm64 ONLY_ACTIVE_ARCH=YES build
```

The arm64 override is required because the vendored iOS `MobileVLCKit.xcframework` is thinned to arm64 only (device and simulator).

When tvOS is relevant:

```bash
xcodebuild -project Ithaca.xcodeproj -scheme Ithaca-tvOS -configuration Debug -destination 'generic/platform=tvOS Simulator' ARCHS=arm64 ONLY_ACTIVE_ARCH=YES build
```

The arm64 override is also required for the vendored tvOS
`TVVLCKit.xcframework`; its slices are likewise thinned to arm64 only.

For docs-only changes, a build is normally unnecessary. Verify the file and `git status --short`.

## App Store Release

- One command uploads both apps (`Ithaca` for iOS, `Ithaca-tvOS`) with the same version and
  build number, like Argo's and Mise's:
  - `./scripts/deploy.sh beta` (or `testflight`): TestFlight only.
  - `./scripts/deploy.sh` (or `prod`): TestFlight, then both platforms submitted to App Review,
    released on approval, and tagged `v<version>`. It asks before starting; `-y` skips that.
    The first version (1.0) only gets its build attached: submit it from the version page
    with the in-app purchases (`asc.mjs release` exits 3 for it).
  - `./scripts/deploy.sh --preflight` runs only the checks below.
  Checklist for the first release: `docs/app-store-release.md`.
- Prerequisites: `xcodegen`, `git-cliff`, Node, and `.asc.local` (git-ignored; the App Store
  Connect API key flags, copied from Argo's) with its key in `~/.private_keys`. The app
  record `com.inceptyon.ithaca` must exist in App Store Connect (platforms iOS and tvOS).
  `claude` on PATH is optional; it only polishes the notes.
- Preflight refuses to archive when: the git tree is dirty; `.asc.local` or its key is
  missing; the app record doesn't exist; or the VLCKit in `Frameworks/` is not Ithaca's
  TrueHD build. Releases ship that build (`docs/playback.md` → "Dolby TrueHD decoding"):
  each framework's `vlckit-installed.txt` must name `VLCKIT_VERSION` from `install_vlckit.sh`
  (`3.7.4-ithaca2`), and each device binary's Mach-O UUID must differ from the stock
  archive's (downloaded once, SHA-256 verified, UUIDs cached in `.build/release/`). Fix with
  `rm -rf Frameworks/MobileVLCKit.xcframework Frameworks/TVVLCKit.xcframework && ITHACA_VLCKIT_CACHE_DIR=.build/vlckit/out ci_scripts/install_vlckit.sh && git checkout Frameworks/VLCKit-VERSION.txt`.
- A menu picks the bump: build number only (the default, and what runs without a terminal or
  with `-y`), or patch, minor or major on `MARKETING_VERSION` too. The run writes both into
  `project.yml`, runs `xcodegen generate` (then restores the checked-in `xcshareddata`
  schemes), and `scripts/whats_new.sh` writes `docs/app-store/what-to-test.txt` from the
  commits since the previous `build/<n>` tag, plus `docs/app-store/whats-new.txt` and this
  version's `CHANGELOG.md` section from the last `v<version>` tag,
  archives both schemes with automatic signing (`-allowProvisioningUpdates` and the API key
  flags), and uploads with `scripts/ExportOptions.plist`. It then commits the bump, notes
  and changelog, tags `build/<n>`, pushes, and `scripts/asc.mjs` sets "What to Test" on both
  builds and keeps the internal group "Inceptyon" on every build; `prod` then runs
  `asc.mjs release`.
- A failure before the first upload puts the bump back; after an upload the build number
  stays spent.

## Git and Push Expectations

- Check `git status --short` before editing and before finishing.
- Assume unrelated changes belong to other agents. Do not revert, stage, commit, or overwrite them.
- If asked to commit/push without branch instructions, use the current branch.
- If asked to commit with unrelated changes present, commit only your changes.
- Avoid destructive commands unless the user explicitly requested them.
- Before publishing, inspect the diff and confirm it matches the requested scope.

## Documentation Maintenance

- Keep docs operational and current; avoid broad rewrites without need.
- Update the relevant `docs/` topic file when changing implementation flow,
  ownership boundaries, reusable components, settings, or verification steps.
- Update `docs/codebase-map.md` when moving boundaries or adding major modules.

## Common Traps

- Forgetting `xcodegen generate` after Swift file adds/removes/renames.
- An app extension's hand-written `Info.plist` must list `arm64` under
  `UIRequiredDeviceCapabilities`, or an App Store upload is rejected as an invalid bundle
  (`IthacaTopShelf/Info.plist`).
- Building iOS simulator without `ARCHS=arm64 ONLY_ACTIVE_ARCH=YES`.
- Treating `Ithaca.xcodeproj` as hand-authored.
- Adding view-level networking instead of using view models and `PlexService`.
- Reintroducing broad backend abstractions while Plex is the only backend.
- Duplicating formatting, state views, posters, or grids instead of checking `Shared/`.
- Putting AVPlayer/VLCKit-specific behavior into generic player UI.
- Assuming docs platform versions are newer than `project.yml`.
- Editing vendored VLCKit binaries or unrelated worktree changes.
- Building `Native/IthacaDovi` with Homebrew's `cargo` (see IthacaDovi Bootstrap).
